入力動画: `$ARGUMENTS`

これは2段階ワークフローの **Step 1（テロップ準備）** です。文字起こしまでを実行し、ユーザーがテロップを確認・修正できるようにファイルを提示してから停止してください。

## 実行手順

1. **入力ファイル確認**
   - `input/` 配下に `$ARGUMENTS` が存在することを確認する
   - 存在しなければユーザーに伝えて停止

2. **環境チェック**
   - `.env` に `OPENAI_API_KEY` と `GEMINI_API_KEY` が設定されているか軽く確認
   - `node_modules/` がなければ `npm install` を案内（ただし勝手に実行しない）

3. **preprocess を実行**
   - `npm run preprocess -- "$ARGUMENTS"` を実行
   - これで以下が生成される:
     - `work/<name>/audio_normalized.wav`
     - `work/<name>/silences.json`
     - `work/<name>/transcript.json`
     - `work/<name>/transcript_edit.md` ← これがユーザー編集用
   - 既にキャッシュがあればスキップされる（Whisper API課金は1回だけ）

4. **テロップファイルを読んで誤認識候補をハイライト**
   - `work/<name>/transcript_edit.md` を Read で開く
   - 以下のパターンを目視で抽出してリストアップする:
     - **カタカナ語**: 短いカタカナ列で意味が通らないもの（例: "キャンバー"→Canva）
     - **英単語**: ASCII英字を含むセグメント。スペル、複合語が崩れているもの（例: "nanova72"→nano banana 2）
     - **固有名詞・人名**: 不自然な漢字混じり（例: "瀬直"→せなお）
     - **数字+英語の組み合わせ**: バージョン番号や型番の誤認識
   - 該当が多い場合は最も怪しい上位5〜10件に絞る
   - 各候補について「セグメント番号」「現在の表記」「推測される正しい表記」を表として表示

5. **停止メッセージを表示**

   以下を含む整理されたメッセージを必ず表示する:

   ```
   ## ✋ Step 1 完了。テロップ確認をお願いします

   ### 編集ファイル
   <フルパス>

   ### Whisperが間違えていそうな箇所
   <表 or 箇条書き>

   ### 編集ルール
   - 角括弧 [#番号 開始-終了] は絶対に変更しない
   - 行の追加/削除/並び替えは禁止
   - 角括弧の右側のテキストだけを編集する
   - 改行は入れない（自動改行ロジックが処理する）

   ### 修正が完了したら
   /video-finish "$ARGUMENTS"
   を実行してください。本編動画のレンダリングまで一気に完了します。
   ショート動画もほしい場合は別途
   /edit-short "$ARGUMENTS" 2
   を実行してください。
   ```

6. **絶対にやらないこと**
   - `npm run main` `npm run short` などのレンダリング系コマンドを実行しない
   - jetcut / broll / Renoise を呼び出さない
   - ユーザーに代わってテロップファイルを書き換えない
   - ユーザーから次の指示が来るまで作業を続けない
